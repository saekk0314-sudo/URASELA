# 月次決算

所管は経理財務部（`cfo` エージェント）。CEOは結果を確認して承認キューとオーナー報告にまとめる。

## 0. 前提の確認

- 実データ（仕訳帳・証憑・明細）は**非公開リポジトリ**にしか置かない。このセッションに非公開リポジトリ（`urasela-hq` 等）が接続されているか確認する。
- 接続されていない場合: 帳簿の実データを公開リポジトリに保存しない。オーナーに「非公開リポジトリの接続」か「明細の貼り付け」を依頼し、受け取った範囲で集計だけ行い、結果はチャットで返す。

## 1. 明細を集める（オーナー作業: 約5分）

依頼する明細（前月分）:
- 事業用口座の入出金明細CSV
- ココナラ・note・ASP・AdSense・SUZURI・Stripe など、動いているプラットフォームの売上明細
- 経費の領収書・請求書（電子データのまま）

## 2. 記帳と検証

1. `company/finance/accounting-policy.md` の仕訳ルールで `ledger/YYYY.csv` に追記する。証憑のファイル名規則 `YYYYMMDD_取引先_金額` を守る。
2. `node company/tools/ledger.mjs check ledger/YYYY.csv` → エラー0、確認事項を解消。
3. `node company/tools/ledger.mjs tb ledger/YYYY.csv --to YYYY-MM-末日 --sub` → 口座残高・プラットフォーム残高と一致するか照合。
4. `node company/tools/ledger.mjs pl ledger/YYYY.csv --year YYYY --sub` → 月次損益。

## 3. 分析と資金

- 収益源ごとに計画（`company/finance/pl-plan.md` 標準シナリオ）と比較し、±30%超は原因を書く。
- 手元資金 −（納税準備金の残高）＝ 使える資金。翌月の支出起案はこの範囲内。
- 納税準備金の振替額＝当月の営業利益 × 25%（`plan-assumptions.json` の `taxReserveRate`）。
- `company/finance/tax-calendar.md` で翌月・翌々月の期限を確認。

## 4. 出力

1. 非公開リポジトリに `reports/monthly/YYYY-MM.md`（実数字・内訳）。
2. 公開してよい要約（実録メディア用）は、オーナー承認後に公開する前提で下書きだけ作る。
3. 承認キューに: 月次決算の確認、納税準備金の振替依頼、翌月の支出起案。

## 5. オーナーへの報告（チャット）

1. 売上・営業利益・計画比（1行）
2. 収益源の内訳（表）
3. やってほしい操作: 「納税準備口座へ◯円振替（1分）」など
4. 期限が近いもの
