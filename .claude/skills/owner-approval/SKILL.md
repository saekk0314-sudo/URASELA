# 承認処理

## 1. 返事を読み取る

- `承認 A-001 A-003` → 該当IDを承認
- `全部承認` → 承認待ちの全件を承認（ただし「選択肢から選ぶ」形式の項目は推奨案で承認したものとして扱い、その旨を報告で明示する）
- `保留 A-004` / `却下 A-005 理由` → 理由ごと記録
- 回答つきの質問（Q-0xx）→ 回答を記録し、関係する文書（計画・規程）に反映
- `ストップ` → 進行中の施策をすべて止め、止めたものと再開の条件を報告。以後の着手はしない

あいまいな返事は推測で実行しない。推奨案を添えて一度だけ聞き返す。

## 2. 記録する

1. `company/owner/approvals.md`: 該当項目を「決裁済み」へ移し、結果（承認/保留/却下）と日付を付ける。
2. `company/owner/decision-log.md`: `| 日付 | ID | 決定 | 条件・メモ |` の行を追記する。
3. 継続的な許可（例: プルリクエストの作成、スケジュール実行、包括承認の型）を含む決定は、`CLAUDE.md` の「オーナーの決定事項」にも1行で反映する。

## 3. 動く

- 承認された仕事は、その場でできる範囲に着手する（L0/L1の作業）。
- オーナーの操作が必要なもの（アカウント開設・送信・振替）は、手順と所要時間をまとめて渡す。
- 却下されたものは代替案を次の週次会議で出す（その場で食い下がらない）。

## 4. 報告（チャット）

1. 受け付けた決裁の一覧（ID・結果）
2. これから着手すること
3. オーナーにやってほしい操作（手順・所要時間）
