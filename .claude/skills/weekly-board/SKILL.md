# 週次経営会議

CEO（AI）が議長。オーナーの作業は「承認・予約・送信」で合計30分以内に収める。

## 1. 現在地を読む（5分）

1. `CLAUDE.md`、`company/README.md`（現在地）
2. `company/owner/approvals.md`（承認待ち）と `company/owner/decision-log.md`（直近の決裁）
3. 直近の `company/reports/weekly/*.md`
4. `company/strategy/roadmap.md` の今のフェーズと、`company/finance/pl-plan.md` の今月の計画値（標準シナリオ）

## 2. 数字を集める

- オーナーが送ったスクショ・数字（GA4・ココナラ・note・X）を `company/strategy/kpi.md` の指標に転記する。
- 届いていなければ止まらずに進め、レポートに「未取得」と書き、最後に「スクショ3枚」を依頼する。
- 計画比±30%を超えた指標は `strategy` エージェントに原因の仮説と打ち手を出させる。

## 3. 今週の計画を作る

| 部門 | 出すもの |
| --- | --- |
| `cmo` | 投稿計画の表＋本文一式（X: 1日2〜3本×7日、note: 1本）。予約しやすいよう日時つき |
| `sales` | 出品の改善点、提案・個別提案の文面、問い合わせへの返信文、保守提案 |
| `cto` | 今週の開発タスク（受け入れ条件つき）と本番反映が必要なもの |
| `cfo` | 今週・来週の期限、入金予定、支出の起案 |
| `legal` | 上の公開物すべての公開前チェック（OK/要修正/NG） |

小さな仕事はCEOが自分でやる。部門エージェントは量が多い・専門的・並行できる仕事にだけ使う。

## 4. 記録する

1. `company/reports/weekly/YYYY-Www.md` を作る（ISO週番号）。構成: 結論 / 数字（計画比）/ 先週やったこと / 今週の計画 / 承認事項 / オーナー作業。
   - 実際の売上金額・顧客名は書かない（非公開リポジトリが接続されていればそちらに書き、ここには「計画比◯%」まで）。
2. 新しい承認事項を `company/owner/approvals.md` に追加（ID・内容・推奨・選択肢・見込み時間・期限）。
3. `company/README.md` の「現在地」を更新。
4. 作業ブランチにコミットしてプッシュ。

## 5. オーナーへの報告（チャット）

15行以内。この順番で書く。

1. **結論**（今週の勝負どころを1行）
2. **数字**（北極星＝営業利益の進捗、計画比）
3. **承認してほしいこと**（`承認 A-0xx` と返すだけで済む形。推奨つき）
4. **やってほしい操作**（例: 「Xで7本予約（10分）→ 本文は reports/weekly/… の◯章」）

文面一式はファイルにまとめ、チャットにはその場所と要点だけを書く。
